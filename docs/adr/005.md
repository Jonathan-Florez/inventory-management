# ADR-005: price como Numeric(10,2), no Float

## Contexto
La migración inicial generó price como Float por el tipo de dato usado
en el modelo Python original (float).

## Decisión
price se tipa como Decimal en Python y se persiste como Numeric(10,2)
en Postgres.

## Alternativas consideradas
- Float: descartado. Los Float no representan exactamente
  la mayoría de valores decimales — errores de redondeo diminutos pero
  reales y acumulables  El dashboard del PDF suma cantidad × precio sobre todo el inventario, lo
  que amplifica cualquier error de redondeo acumulado. Lo cual no es aceptable para un inventariado

## Consecuencias
- Cálculos de valor de inventario exactos, sin arrastre de error binario.
- Ligero costo de legibilidad: Decimal requiere manejo explícito en
  Python (no se comporta como un float nativo en todas las operaciones).

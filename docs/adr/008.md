# ADR-008: SELECT FOR UPDATE para actualización atómica de stock

## Contexto
El PDF exige que registrar un movimiento actualice el stock del producto
"de forma atómica" (sección "¿Por qué esta prueba es diferente?", punto 5).
Sin un mecanismo de bloqueo, dos movimientos concurrentes sobre el mismo
producto podrían leer el mismo valor de quantity, validar stock de forma
independiente, y ambos escribir — generando un resultado incorrecto


## Decisión
ProductRepository.get_by_id_for_update() usa SELECT ... FOR UPDATE
(vía .with_for_update() de SQLAlchemy) al leer el producto dentro de
MovementService.create_movement(). Esto bloquea la fila hasta que la
transacción actual termine (commit o rollback), forzando a una segunda
transacción concurrente sobre el mismo producto a esperar. La creación del
movimiento y la actualización de product.quantity se commitean juntas en
una sola transacción.

## Alternativas consideradas
- Sin ningún mecanismo de bloqueo: descartado 

## Consecuencias
- Garantiza atomicidad e integridad del stock bajo escritura concurrente.
- Trade-off aceptado: una segunda request sobre el mismo producto espera
  (no falla) hasta que la primera transacción termine — comportamiento
  correcto para este caso de uso, donde las transacciones son cortas.
